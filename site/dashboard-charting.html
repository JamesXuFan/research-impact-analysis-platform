app/Home.py · app/pages/*.py

How Data Gets "Read" — the Caching Layer数据是怎么"读取"的 — 缓存层

app/lib.py

Streamlit's execution model is "every time the user touches a widget (slider, dropdown...), the whole page script reruns start to finish." If every rerun re-read parquet and re-ran groupby, one slider tick would take several seconds. lib.py's entire reason for existing is to centralise this caching layer. Streamlit的执行模型是"每次用户碰一下控件(滑块、下拉框……)，整个页面脚本从头到尾 重新跑一遍"。如果每次都重新读parquet、重新groupby，点一下滑块要等好几秒。 lib.py存在的唯一理由就是把这一层"缓存"集中管理。 

@st.cache_data(show_spinner="Loading publication data (deduplicated)…")
def load_deduplicated():
    return prepare.prepared_deduplicated()

@st.cache_data(show_spinner="Computing Q1 share by university…")
def get_q1_share_by_university():
    return journal_tier.q1_share_by_university(load_deduplicated())
  • @st.cache_data: a decorator — placed one line above a function definition, Streamlit remembers "this function was called once with this set of arguments," and returns the cached result directly on a second call with the same arguments instead of re-running the body. "Same arguments" is decided by hashing them.@st.cache_data：装饰器(decorator)——加在函数定义上面一行，Streamlit会记住"这个函数、用这组参数调用过一次"，第二次用同样的参数调用时直接返回上次缓存的结果，不再重新执行函数体。判断"参数是否相同"是通过给参数计算哈希值实现的。
  • show_spinner="...": the spinner text shown while a cache miss is genuinely computing — not required, but with it the user knows exactly what step they're waiting on, instead of a generic blank spinner.show_spinner="..."：缓存未命中、真的在计算时，页面上显示的转圈提示文字——不加也能用，但加了用户能知道"现在具体在等哪一步"，而不是一个空白的通用转圈图标。
  • Why no function takes a DataFrame argument, calling load_deduplicated() internally to get its own data instead: the comment at the top of lib.py explains this directly — passing a whole DataFrame as an argument to an @st.cache_data-wrapped function forces Streamlit to hash the entire DataFrame just to decide "is this call the same as last time," and that hash itself can be slower than just recomputing the result. Letting a function call another already-cached function internally (load_deduplicated() is itself @st.cache_data) means the two cache layers each hit independently, with no need to pass a large object as an argument.为什么每个函数都不接收DataFrame参数，而是在函数体内部自己调用load_deduplicated()去拿数据：lib.py顶部的注释专门解释了这一点——如果把一整个DataFrame当参数传给一个被@st.cache_data包装的函数，Streamlit得对整个DataFrame算一次哈希才能判断"这次调用和上次是不是同一组参数"，这个哈希计算本身可能比重新算一次结果还慢。让函数自己内部调用另一个同样被缓存的函数（load_deduplicated()本身也是@st.cache_data），两层缓存分别命中，就不需要传大对象当参数。
  • The call chain is layered: page code calls lib.get_xxx() → lib.get_xxx() calls load_deduplicated() for data, then the real computation function in src/p36/analysis/ → the computation function never touches the caching machinery directly. lib.py's top comment says it plainly: "if a number looks wrong, the bug is in src/p36/, not here" — lib.py's only job is "catch the result, cache it," no analysis logic of its own.调用链是分层的：页面代码调 lib.get_xxx() → lib.get_xxx() 调 load_deduplicated() 拿数据、再调 src/p36/analysis/ 里的真正计算函数 → 计算函数从不直接接触缓存机制。lib.py顶部注释写得很直接："如果一个数字看起来不对，bug在src/p36/里，不在这里"——lib.py只负责"接住结果、缓存住"，不做任何分析逻辑。
Relation to the previous note跟第一篇的关系 load_deduplicated() internally calls prepare.prepared_deduplicated(), which underneath that calls the previous note's p36.dataset.load_deduplicated() to read the parquet file — the prepare.py layer additionally applies add_derived_flags() after reading the parquet, so the DataFrame a Streamlit page gets already carries columns like is_q1, is_international, and page code never has to compute them itself. load_deduplicated() 内部调的 prepare.prepared_deduplicated()， 再往下才是第一篇讲过的 p36.dataset.load_deduplicated() 读parquot文件—— prepare.py这一层是在读完parquot之后再叠加一次add_derived_flags()， 所以Streamlit页面拿到手的DataFrame已经带着is_q1、is_international 这些标记列了，不需要页面代码自己再算一次。

How Sections Are Designed板块是怎么设计的

app/theme.py

Every page opens with the same four-step combo: st.set_page_config(...) → theme.inject() → theme.header(...) → theme.question_panel([...]). Every subsection below that repeats theme.anchor(id) → st.subheader(...) → chart → theme.rule(). 每个页面开头都是同一套四连招：st.set_page_config(...) → theme.inject() → theme.header(...) → theme.question_panel([...])。往下每个小节再重复 theme.anchor(id) → st.subheader(...) → 图表 → theme.rule()。

theme.inject()

The first function every page calls, doing two things today: registering the global Altair theme and injecting one whole block of CSS. (Until 2026-09-13 it also mounted a cross-page-jump "bridge" — see the note below.)每页最先调用的函数，今天做两件事：注册Altair全局主题、注入一整块CSS。（2026-09-13之前还会挂载一个跨页跳转的"桥"——见下面的说明。）

st.markdown(
    f"""<style> ... </style>""",
    unsafe_allow_html=True,
)
  • st.markdown(html string, unsafe_allow_html=True): Streamlit's st.markdown is meant for "writing documents" (headings, bold, lists), but feeding it a whole <style>...</style> or <div>...</div> string, with unsafe_allow_html=True explicitly turned on, lets you insert arbitrary HTML/CSS into the page — this is the underlying trick behind every visual effect in theme.py; header(), question_panel(), anchor(), and rule() are all built on exactly this move.st.markdown(html字符串, unsafe_allow_html=True)：Streamlit本来是把st.markdown当成"写文档"用的(标题、加粗、列表)，但把一整段<style>...</style>或<div>...</div>字符串传进去、并显式打开unsafe_allow_html=True，就能往页面里插入任意HTML/CSS——这是整个theme.py视觉效果的底层技巧，header()、question_panel()、anchor()、rule()全都是靠这一招实现的。
  • CSS selectors heavily use the pattern div[data-testid="stMetric"]: data-testid is an attribute Streamlit's rendered HTML elements carry themselves, specifically designed so external CSS/test code can target a component precisely — far more stable than guessing at class names.CSS选择器大量用div[data-testid="stMetric"]这种写法：data-testid是Streamlit渲染出的HTML元素自带的属性，专门为了"外部CSS/测试代码能精确定位到某个组件"设计的，比瞎猜class名字稳定得多。

Once every sub-question became answerable on the page that asks it, there was nothing left for a cross-page link to point at, so this function and its call site were deleted along with the "elsewhere" status. See the Sub-Question Navigation Close-Reading for the full technique, kept there as history. 2026-09-13之前，question_panel()里"answered on another page"的问题，点击后要跳到另一个页面的指定位置——单纯的 st.markdown(..., unsafe_allow_html=True)做不到这件事，因为Streamlit的 前端不会执行插进去的<script>标签。inject()以前最后 会调用_cross_page_scroll_bridge()，用st.iframe()渲染一段 真正会执行的内联HTML/JS——通过window.parent读URL里的#锚点， 轮询等目标元素出现，找到了就scrollIntoView。等到每一条子问题都能在 提出它的那一页里直接回答之后，跨页链接就没有什么可指向的了，这个函数连同它的调用 点、以及"elsewhere"状态一起被删掉了。完整技巧见子问题 跳转机制精读，那边作为历史记录保留着。
theme.header(title, caption, shape, color)

The "colour block + big title + thick black rule + caption" combo at the top of every page.每页最上面那个"色块 + 大标题 + 粗黑线 + 说明文字"的组合。

GO8 BENCHMARKING
  • The shape argument only takes three values — square/circle/triangle, mapped to red/blue/yellow respectively — and that's not arbitrary: the source comment says it's a nod to the Bauhaus painter Kandinsky's shape-colour associations (square-red, circle-blue, triangle-yellow); each of the 6 analysis pages has its own fixed shape+colour, so a glance at the colour block tells a user which page they're on.shape参数只有三个取值——square/circle/triangle，分别对应红/蓝/黄——这不是随便选的：源码注释里写明是致敬包豪斯(Bauhaus)画家康定斯基提出的"形状-颜色"对应关系(正方形配红色、圆形配蓝色、三角形配黄色)，6个分析页面各自固定用哪个形状+颜色，让用户扫一眼色块就能区分自己在哪个页面。
  • Of the three shapes, square and circle are both drawable in plain CSS (border-radius:50% for a circle); triangle is the classic pure-CSS trick — a zero-width, zero-height div, with transparent border-left/border-right and a solid border-bottom drawing a triangle, no image or SVG required.三种形状里，square和circle都是CSS就能画的(border-radius:50%画圆)，triangle是纯CSS的经典技巧——一个宽高为0的div，靠border-left/border-right透明、border-bottom实色画出一个三角形，不需要任何图片或SVG。

  • (*item, None)[:3]: compact but worth unpacking. item may be a 2-tuple (question, status) or a 3-tuple (question, status, anchor). *item first "spreads" the tuple into individual elements, appends one None, forming a new tuple of at least 3 elements, then [:3] takes only the first 3 — so whether the caller passed 2 or 3 elements, the unpacked anchor_id is either a real anchor id or None, without writing an if len(item) == 3 check.(*item, None)[:3]：一个紧凑但值得拆开看的写法。item可能是2元组(问题, 状态)或3元组(问题, 状态, 锚点)。*item先把元组"展开"成单个元素，后面补一个None，拼成至少3个元素的新元组，再用[:3]只取前3个——这样不管调用方传了2个还是3个元素，解包出来的anchor_id要么是真的锚点id，要么就是None，不用写if len(item) == 3这种判断。
  • _STATUS_STYLE is a dict whose keys are the 3 status strings today ("done"/"partial"/"open" — a 4th, "elsewhere", existed until 2026-09-13) and whose values are a 3-tuple (icon, background, foreground) — each item just looks up the corresponding visual style from the dict, instead of a long if/elif chain._STATUS_STYLE是一个字典，key是今天的3个状态字符串("done"/"partial"/"open"——第4个"elsewhere"存在到2026-09-13为止)，value是一个三元组(图标, 背景色, 前景色)——每一项直接查字典拿到对应的视觉样式，不用写一长串if/elif。
theme.anchor(id) / theme.rule()

Two functions only a few lines long — a "jump landing spot" and a "divider," respectively.两个只有几行的小函数，分别是"跳转落点"和"分隔线"。

def anchor(anchor_id):
    st.markdown(f'<div id="{anchor_id}" class="qanchor"></div>', unsafe_allow_html=True)
  • Just inserts an empty, invisible <div id="..."> — the browser natively supports "jump to the element with this id" (append #that-id to the URL); this function's only job is "put something jumpable in the right place," paired with the scroll-margin-top: 90px CSS in inject(), so the landing spot isn't hidden under Streamlit's own top toolbar after the jump.就是插入一个空的、看不见的<div id="...">——浏览器原生支持"跳到某个id的元素"这个功能(URL加#那个id)，这个函数只是负责"在正确的位置放一个能被跳到的东西"，配合inject()里CSS的scroll-margin-top: 90px，跳过去的时候不会被Streamlit自己的顶部工具栏挡住标题。
  • Placement matters: it must sit immediately above the corresponding st.subheader(...), so the landing spot and the visual heading line up.放置位置很讲究：必须紧挨在对应的st.subheader(...)之上，这样跳转落点和视觉标题对得上。

How a Chart Gets "Built"图表是怎么"构"出来的

Altair (Vega-Lite) · theme.py's charting infrastructureAltair(Vega-Lite) · theme.py 的图表基础设施

Every chart on the whole platform uses only Altair (bundled with Streamlit, no extra install). Altair's core idea is called "grammar of graphics": rather than saying "draw a bar," you say "which column maps to the x-axis, which to the y-axis, which to colour," and the library figures out the layout itself. 整个平台图表只用Altair一个库(Streamlit自带，不用额外装)。Altair的核心思想叫 "图形语法"(grammar of graphics)：不直接说"画一根柱子"，而是说"数据的哪一列 对应x轴、哪一列对应y轴、哪一列对应颜色"，剩下的排布交给库自己算。

bar = (
    alt.Chart(bar_df)

The same numeric column, marked Q vs. O, produces different axis ticks and sort behaviour — getting the type wrong is the most common beginner mistake in Altair.x=alt.X("university:N", ...)：冒号后面的字母是数据类型标注，Altair的语法里必须写——N=nominal(无序分类，比如大学名)，Q=quantitative(数值)，O=ordinal(有序分类，比如年份)，T=temporal(日期时间)。同一列数字，标成Q和标成O画出来的轴刻度、排序方式都不一样，写错类型是Altair新手最容易踩的坑。

  • The binary colour-mapping trick: is_client is a boolean column (is this row Sydney), and scale=alt.Scale(domain=[True, False], range=[theme.RED, theme.BLUE]) explicitly pins "True (Sydney) → red, False (other universities) → blue" — without scale, Altair picks colours itself and there's no guarantee Sydney is always red; this "pin a dedicated colour to the key category" pattern shows up in nearly every chart.color的二元映射技巧：is_client是一个布尔列(这一行是不是悉尼)，scale=alt.Scale(domain=[True, False], range=[theme.RED, theme.BLUE])显式规定"True(悉尼)→红色，False(其它大学)→蓝色"——不写scale的话Altair会自己挑颜色，不保证悉尼总是红色，这种"给关键类别固定专属颜色"的写法在几乎每张图里都用了一遍。

  • alt.themes.register(name, function returning a config dict): registers a whole set of default styles (axis colour, font, legend position, bar stroke...) as a reusable "theme" — the dict _bauhaus() returns configures default styles from axis to legend to every mark type (bar/line/arc).alt.themes.register(名字, 返回配置字典的函数)：把一整套默认样式(坐标轴颜色、字体、图例位置、柱状图描边……)注册成一个可复用的"主题"，_bauhaus()函数返回的字典里配置了从axis到legend到bar/line/arc每种图形的默认样式。
  • alt.themes.enable("bauhaus"): activates the theme — once active, every Altair chart created afterwards on the page automatically picks up this configuration unless it explicitly overrides a style. An advanced example: the radar chart is "faked"进阶例子：雷达图是"骗"出来的

Vega-Lite has no polar coordinate system — the Go8 Benchmarking page's radar chart converts "angle + radius" into "x, y" by hand.Vega-Lite没有极坐标系统，Go8 Benchmarking页面的雷达图是手动把"角度+半径"换算成"x,y"画出来的。

angles = [2 * np.pi * i / n - np.pi / 2 for i in range(n)]  # starting from 12 o'clock, clockwise从12点钟方向开始，顺时针

def _radar_points(series_name, values):
    pts = list(zip(values, angles, radar_labels))
    pts.append(pts[0])  # close the shape: repeat the first point again at the end闭合图形：把第一个点再重复一次接到末尾
    return [
        {"series": series_name, "order": i, "r": r,
         "x": r * np.cos(a), "y": r * np.sin(a)}
        for i, (r, a, label) in enumerate(pts)
    ]
  • Each metric is first normalised into a 0~1 "radius" r (min-max scaling — the lowest of the 8 universities is 0, the highest is 1), paired with a pre-assigned angle a (dividing the 360° circle evenly among the metrics via 2π×index/total).每个指标先归一化成0~1的"半径"r(min-max缩放，8所大学里最低的算0、最高的算1)，再配一个提前分好的角度a(用2π×序号/总数把一圈360度均匀切给几个指标)。
  • x = r·cos(a), y = r·sin(a): the polar-to-Cartesian formula from high-school maths — this is exactly what converts "this metric is ranked such-and-such, and its value is this" into an (x, y) point that a plain scatter/line chart can draw.x = r·cos(a)、y = r·sin(a)：高中学过的极坐标转直角坐标公式——本质上就是把"这个指标排第几、这个指标的值是多少"，转换成一个普通散点图/折线图能画的(x, y)点。
  • pts.append(pts[0]): a line chart needs to "close into a polygon," so the starting point is deliberately repeated once more at the end — skip this and the shape is missing one edge, a hexagon drawn as an open six-segment line instead.pts.append(pts[0])：折线图要"连成一个封闭的多边形"，所以特意把起点在末尾再重复一遍——不加这一步，图形会缺一条边，六边形会画成一个开口的六段折线。
  • Once (x, y) is computed, the rest is a plain alt.Chart(radar_df).mark_line(...).encode(x="x:Q", y="y:Q", order="order:Q", color="series:N") — the radar chart "looks like" polar coordinates, but as far as Altair is concerned it's always just an ordinary Cartesian line chart, with coordinates pre-computed in pandas/numpy.算出(x, y)之后，剩下就是普通的alt.Chart(radar_df).mark_line(...).encode(x="x:Q", y="y:Q", order="order:Q", color="series:N")——雷达图"看起来"是极坐标，但对Altair来说，它自始至终只是一张普通的直角坐标折线图，坐标是提前在pandas/numpy里算好的。

From pandas to Altair: What Shape the Data Needs从pandas到Altair：数据要长成什么样

Altair requires "tidy data": each row is one observation, each column is one variable. But pandas operations like groupby() and value_counts() often produce a Series (category as the index), or a "wide table" (each category gets its own column) — these usually need a shape change before Altair can eat them. Altair要求"整洁数据"(tidy data)：每一行是一个观测，每一列是一个变量。 但groupby()、value_counts()这些pandas操作算出来的常常是一个 Series(用类别当索引)，或者一张"宽表"(每个类别自己占一列)——喂给Altair之前通常要转一次形状。

Series → two-column DataFrame: .rename_axis().reset_index(name=...)
q1_uni = get_q1_share_by_university().sort_values(ascending=False)
# q1_uni is now a Series: the index is university name, the value is Q1 share — Altair can't consume an "index" directlyq1_uni 现在是一个Series：索引是大学名，值是Q1份额——Altair不能直接吃"索引"
q1_uni_df = q1_uni.rename_axis("university").reset_index(name="q1_share")
# now it's a two-column table: university | q1_share转完是一张两列的表：university | q1_share
  • .rename_axis("university"): gives the Series's index a name (it might have had none, or a different one)..rename_axis("university")：给Series的索引起一个名字(原来索引可能没名字，或者叫别的)。
  • .reset_index(name="q1_share"): "pulls the index off" into a plain column, and name= simultaneously names what was the value column — chained together, a Series with "university name as index" becomes a standard two-column DataFrame with university and q1_share, ready to feed alt.X("university:N") and alt.Y("q1_share:Q")..reset_index(name="q1_share")：把索引"拆下来"变成普通的一列，name=参数顺便给原来的值那一列起名字——两步连起来，一个"大学名当索引"的Series就变成了一张university、q1_share两列的标准DataFrame，正好可以喂给alt.X("university:N")、alt.Y("q1_share:Q")。
  • This combination appears dozens of times across the six pages — the most common fixed idiom for "pandas aggregation result → Altair input," worth memorising.这个组合在6个页面里出现了几十次，是"pandas聚合结果 → Altair输入"最常见的固定写法，值得背下来。
Wide table → long table: .melt()

Journal Tier page: two numbers, "highly-cited share" and "uncited share," need to become one grouped, colour-coded bar chart.Journal Tier页面："高被引占比"和"零引用占比"两个数字，要画成同一张图里、按颜色区分的分组柱状图。

shares_long = quartile_df.melt(
    id_vars="quartile",
    value_vars=["top_decile_share", "uncited_share"],
    var_name="metric", value_name="share",
)
# before (wide): quartile | top_decile_share | uncited_share      one row per tier转前(宽表)：quartile | top_decile_share | uncited_share      一行一个分位
# after (long): quartile | metric | share                         one row per (tier, metric) pair转后(长表)：quartile | metric | share                        一行一个"分位+指标"组合
  • id_vars="quartile": the column kept unchanged, used as the "identifier column" during the transform.id_vars="quartile"：转换时保持不变、当"标识列"用的列。
  • value_vars=[...]: the columns to be "taken apart" — originally two columns side by side, they become different rows of the same share column, with a metric column marking which original column each row came from.value_vars=[...]：要被"拆开"的那几列——原来是两列并排放，拆开之后变成同一列share里的不同行，用metric列标记这一行原来是哪一列。
  • Why take it apart at all: Altair uses color="metric:N" to assign "highly cited" and "uncited" different colours, paired with xOffset="metric:N" to place the two bars for the same tier side by side — this "group/colour by a column's values" mechanism requires the data to already be a "long table," where each row maps to exactly one colour. If the two numbers were still two columns side by side in the same row, Altair would have no way to pull a colourable category value from a "column name" itself.为什么要拆：Altair用color="metric:N"给"高被引"和"零引用"分配不同颜色、再配xOffset="metric:N"让同一个分位下两根柱子并排放——这套"用一列的值来分组/上色"的机制，前提是数据已经是"长表"，每一行只能对应一种颜色。如果两个数字还并排放在同一行的两列里，Altair没法从"列名"本身取到一个能拿来上色的类别值。
Compute a column on the fly, then chart it: .assign()
highly_cited_df = field_summary.reset_index(names="field").assign(
    highly_cited_count=lambda d: (d["publications"] * d["top_decile_share"]).round().astype(int)
)
  • .reset_index(names="field"): the DataFrame-flavoured version of the earlier rename_axis+reset_index(name=) combo (the index already has a name here, so it's renamed directly via reset_index's names= argument, no separate rename_axis needed)..reset_index(names="field")：跟前面的rename_axis+reset_index(name=)是同一件事的DataFrame版本(索引本来就有值了，直接在reset_index里用names=参数重命名，不用先rename_axis)。
  • .assign(new_col=lambda d: expression): method-chaining style new column — the d inside lambda d: ... refers to the DataFrame at the moment .assign() is called, which lets a whole pipeline be written as one chain (df.reset_index(...).assign(...).sort_values(...)) without repeatedly assigning to temp variables in between. Here it computes "the absolute count of highly-cited papers" = publication count × highly-cited share, rounded to an integer, on the fly..assign(新列名=lambda d: 表达式)：链式(method chaining)风格新增一列——lambda d: ...里的d指的就是.assign()被调用时那一刻的DataFrame本身，好处是可以写成一整条链(df.reset_index(...).assign(...).sort_values(...))而不用中间反复赋值给临时变量。这里现算"高被引论文的绝对数量"= 发文量 × 高被引占比，四舍五入取整。

Syntax Cheat Sheet语法速查表

@st.cache_data
Decorator: on a second call with the same arguments, returns the cached result directly instead of re-running the body. Functions shouldn't take a DataFrame as an argument (hashing it is expensive) — they should fetch their own data internally instead.装饰器：同样参数第二次调用直接返回缓存结果，不重新执行函数体。函数不要接收DataFrame做参数(哈希代价高)，应在函数体内部自己去拿数据。
st.markdown(html, unsafe_allow_html=True)
Nominally a component for rendering Markdown text; with this switch on it can insert arbitrary HTML/CSS, and is the underlying implementation for almost every visual component in theme.py.本来是渲染Markdown文本的组件，打开这个开关后能插入任意HTML/CSS，是theme.py几乎所有视觉组件的底层实现方式。
